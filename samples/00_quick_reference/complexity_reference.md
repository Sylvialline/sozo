# Python 考场复杂度速查

目标不是背表，而是在数据规模未知时快速避开会超时或爆内存的写法。

## 先估算

| 规模 `n` | 通常可考虑 | 警惕 |
|---:|---|---|
| `10^2` | `O(n^3)`（操作很轻时） | Python 三重循环仍应实测 |
| `10^3` | `O(n^2)` | 大对象矩阵的内存 |
| `10^5` | `O(n log n)`、`O(n)` | 循环内切片、反复线性查找 |
| `10^6` | 简单 `O(n)` | Python 整数/元组的内存远大于原始字节 |

考试允许运行数分钟，但真实规模未知：先写清楚的最优常见解，再用计时和小型校验确认。

## 容器

| 操作 | 复杂度 | 考场备注 |
|---|---:|---|
| `list.append(x)`, `list.pop()` | 均摊 `O(1)` | 栈首选 |
| `list[i]` | `O(1)` | 负下标从末尾计 |
| `x in list`, `list.index(x)` | `O(n)` | 高频查询改用 `set`/`dict` |
| `list.insert(0, x)`, `list.pop(0)` | `O(n)` | 队列用 `deque` |
| `list[a:b]` | `O(k)` 时间和空间 | 循环内切片可能把线性算法写成平方 |
| `list.sort()`, `sorted(...)` | `O(n log n)` | 前者原地且返回 `None` |
| `dict`/`set` 查、增、删 | 平均 `O(1)` | 最坏可退化；键必须可哈希 |
| `deque` 两端增删 | `O(1)` | 中间索引/查找不是强项 |
| `heapq` push/pop | `O(log n)` | 默认最小堆；取堆顶 `O(1)` |
| `bisect_left` 查位置 | `O(log n)` | 插入 list 仍是 `O(n)` |
| `Counter.most_common(k)` | 依实现约 `O(n log k)` | 只需最大值时可直接 `max` |

## 字符串与文件

- `text.split()`、`strip()`、`replace()`：`O(len(text))`，并创建新对象。
- `''.join(parts)`：总字符数线性；不要在循环中反复 `result += piece` 拼大文本。
- `re.search` 的实际复杂度取决于模式；避免灾难性回溯的嵌套模糊量词。
- `Path.read_text()` 一次把文件放入内存；巨型文件应逐行遍历。
- `Path.rglob()` 会访问整棵目录树；能限定目录或扩展名就尽早限定。

## 常见算法

| 算法 | 时间 | 额外空间 |
|---|---:|---:|
| BFS / DFS | `O(V + E)` | `O(V)` |
| Dijkstra（二叉堆） | `O((V+E) log V)` | `O(V+E)` |
| 并查集（路径压缩 + 按大小合并） | 近似 `O(1)`/次 | `O(n)` |
| 前缀和预处理 / 区间查询 | `O(n)` / `O(1)` | `O(n)` |
| 二分查找 | `O(log n)` | `O(1)` |
| 排序后双指针 | `O(n log n)` | 取决于排序 |
| `n × m` 网格遍历 | `O(nm)` | 标记可用 `bytearray` 降低内存 |

## Python 内存直觉

- `bytearray(n)` 约 `n` 字节，适合布尔访问标记。
- `[False] * n` 保存的是对象引用数组，远大于 `n` 字节。
- Python `int` 通常是几十字节，`list[int]` 还包含每项引用。
- `[(x, y), ...]` 的元组和整数对象开销明显；超大网格可考虑一维编号。
- 生成器减少峰值内存，但只能单次消费，且不一定比列表更快。

## 一眼可疑的代码

```python
queue.pop(0)                 # BFS 退化：换 deque.popleft()
x in long_list              # 循环内线性查找：换 set
sum(values[:i])             # 每次重算：换前缀和
sorted(values)[0]           # 只要最小值：用 min(values)
result = result + [x]       # 每次复制：用 append
grid = [[0] * m] * n        # 行共享：用列表推导式
```

最后原则：复杂度相同时优先可读、容易验证的版本；优化前用代表数据计时，优化后重新核对答案。
