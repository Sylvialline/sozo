## 已确认的题意要点

- 坐标均非负，但题面没有给出坐标和图形数量的显式上限。
- 长方形的端点格包含在图形中。
- 圆和线段只在其内部与格子的开内部相交时涂色；只相切或只碰格边、格角不计。
- 后画的图形覆盖先画的颜色，但所有绘图颜色均为非白色，因此最终非白区域的包围盒
  等于各图形实际涂色区域包围盒的并。
- 连通只使用上下左右四邻接。
- 问 (5) 先最小化与起点颜色不同的格子数，再最小化包含两端点的路径格数。
- 包围盒左上角或右下角本身可能是白色。

## 优先级最高的改进建议

### 1. 用 `Exam` 按小问停止生成器

当前实现保留 `answers(data)` 生成器作为内部答案流水线，并由五个 `@exam.task`
分别取第 1～5 个答案。`select_answer()` 在取得目标 `yield` 后立即关闭生成器，因此
目标答案之后的算法仍然不会执行。

```powershell
python -u .\2025-8\solve.py
```

只运行一个题组时，把文件末尾暂时写成 `exam.execute(only=task3)`；写入
`answer.json` 时使用 `exam.execute(output=True, only=task3)`。目标 `yield` 之前已经
主动完成的计算仍会执行，因此何时计算、何时 `yield` 仍然值得有意识地安排。

### 2. 让画布依赖包围盒尺寸，而不是绝对坐标

当前画布从全局 `(0, 0)` 开始，内存使用量取决于包围盒右下角的绝对坐标。若一个很小
的图形整体平移到很大的坐标附近，算法会分配远大于实际图形范围的网格。

可考虑记录画布原点，将全局坐标平移到局部坐标，只保留包围盒及路径所需的一格外围。
需要增加的回归数据是：把现有小样例整体平移一个很大的常数，除包围盒坐标外，其余
答案应保持不变。

### 3. 避免缓存只使用一次的全部涂色格

当前图形先建立格子列表，再遍历列表绘制，并把列表保留在每个图形对象中。可考虑：

- 圆和线段边枚举边绘制；
- 长方形逐行绘制，必要时使用列表切片；
- 只有确实会重复使用时才缓存格子集合。

### 4. 减少连通分量中的无关工作

当前并查集会处理白格，并向四个方向重复检查相邻关系。可选方向：

- 使用 `bytearray` 记录访问状态，只对黑、灰格做 BFS/DFS；
- 或继续使用并查集，但只检查右、下两个方向，并避免为无关格执行合并。

通用并查集已经整理为 `utils.DSU`，是否在考试代码中导入或亲手实现由仓库所有者决定。

## 较低优先级的可读性建议

- `typing.List` 在现代 Python 中可以写成内置的 `list[...]`。
- 基类方法若不允许直接调用，使用 `raise NotImplementedError` 比 `...` 更能暴露误用。
- `if`、`return` 与其他语句写在独立行上，更方便断点调试和考场目视检查。
- 四方向相邻关系只读时可使用元组，表达其不会被修改。
- stale heap entry 可以用“弹出值是否等于当前最优值”来判断，减少推理分支。

这些改动的收益低于坐标归一化、停止无关计算和降低画布内存，处理顺序不应颠倒。

## 本题沉淀出的通用资源

- `utils.Exam`、`Series`、`read_data`：题组声明、数据读取、计时和答案输出。
- `utils.DSU`：迭代路径压缩、按大小合并、连通判断、集合大小和集合数量。

暂不提取到全局 `utils`：

- 圆或线段与开放格内部的相交判断：语义高度依赖本题；
- 二元组代价最短路：当前实现与本题“先异色格数、后路径长度”的定义绑定；
- 四方向常量：重写成本低于维护额外接口。
